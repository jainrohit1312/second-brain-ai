# Second Brain — Roadmap

Milestones beyond the current phase, what "v1" means, the risks, the privacy commitments stated as commitments, and the triggers that would force a re-architecture.

Status: draft — scaffold phase. Every milestone below is a target. The phase numbers refer to [TASKS.md](./TASKS.md), which is the executable form of the same plan.

## Milestones

The ordering rationale is one sentence long: **capture is worthless without processing, processing is worthless without recall, and recall is worthless without a surface someone will actually use** — so the milestones follow that chain, and each one leaves a demonstrable capability rather than a half-built layer.

| #       | Theme               | Capabilities it unlocks                                                                                                                                                                    | Why it comes here                                                                                                                                                                                                                                                | Depends on  | Phases                   |
| ------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------ |
| **M0**  | **Scaffold**        | A repository that states and constrains the system: layout, configuration, frozen types, contracts, and documentation.                                                                     | Everything else is written against these contracts. Getting them wrong is cheapest to fix now.                                                                                                                                                                   | —           | 0                        |
| **M1**  | **Capture**         | A real extension captures a real page read, survives being offline, syncs a batch, and the row is in Postgres with correct ownership. The exclusion invariant is enforced and tested.      | This is the only milestone where privacy is load-bearing before usefulness, and the security model can only be validated against real capture.                                                                                                                   | M0          | 1                        |
| **M2**  | **Understanding**   | Events become documents with extracted text, embedded chunks, topics, and a trustworthy importance score.                                                                                  | Recall is impossible without retrievable units. This milestone produces the substrate, not the product.                                                                                                                                                          | M1          | 2                        |
| **M3**  | **Memory**          | Documents become durable, evidenced, temporally-valid statements about the user — and documents with nothing durable produce nothing.                                                      | **This is the milestone that decides whether the product is what it claims to be.** Everything before it is plumbing; everything after it is unusable if this is wrong.                                                                                          | M2          | 3                        |
| **M4**  | **Recall**          | A question returns ranked, cited evidence, with a measured baseline and a regression gate.                                                                                                 | The first milestone where the system answers a question no document answers. Also the first where quality is a number rather than an opinion.                                                                                                                    | M3          | 4                        |
| **M5**  | **Product**         | Chat with citations, an activity dashboard, memory review, and settings a person can operate.                                                                                              | The system becomes usable, and the first honest judgement of whether the memory layer was right becomes possible — because a human is now reading it.                                                                                                            | M4          | 5                        |
| **M6**  | **Second device**   | Android app sessions, Room queue, the same protocol, and the same scoring fixtures passing on a second platform.                                                                           | Deliberately after the product exists, because a second client doubles the surface. It depends on nothing in the processing or retrieval pipeline, so it can run in parallel if a second contributor appears.                                                    | M1          | 6                        |
| **M7**  | **Durability**      | Reranking and semantic chunking resolved, retention and deletion real, CI gates, backups with a tested restore, and a runbook.                                                             | **M7 is what makes M1–M6 v1 rather than a demo.** It is the milestone most likely to be skipped and the one whose absence is discovered at the worst possible time.                                                                                              | M4, M5, M6  | 7                        |
| **M8**  | **Reflection**      | The system surfaces patterns the user did not ask about: what a topic's trajectory looks like, which decisions have gone stale, which tasks are unaddressed, how attention is distributed. | This is the pillar the product was named for and it is deliberately last, because reflection is only meaningful once the memory layer is trustworthy. A reflection feature built on noisy memories produces confident nonsense.                                  | M7          | Post-v1                  |
| **M9**  | **Local-only mode** | Embeddings, retrieval, and distillation running on the user's own hardware, so no content leaves the device.                                                                               | The strongest possible version of the privacy promise. Requires a local model that passes E3 and E17, and an on-device vector store. This is a re-architecture of where the pipeline runs, not a setting.                                                        | M7 + E3/E17 | Post-v1                  |
| **M10** | **Multiple people** | Several users, each fully isolated, with their own providers and costs.                                                                                                                    | The schema is already `user_id`-scoped with RLS, so the database work is mostly done. What is not done is anything operational or economic: per-user provider keys, cost attribution, abuse handling.                                                            | M7          | Post-v1                  |
| **M11** | **Team memory**     | Shared topics and memories across a small group, with per-item visibility.                                                                                                                 | Named because it is the most requested thing that is not this product. It requires a sharing model that does not exist, a different privacy story, and a schema change that RLS-per-user actively resists. See [the non-goals](./PROJECT_OVERVIEW.md#non-goals). | M10         | Deliberately unscheduled |

## What "v1" means

**v1 is M7: a system one person can rely on.** Concretely, and checkably, v1 means all of the following are true at once.

| #   | v1 requires                                                                     | Checked by                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Capture never loses an event it accepts, and never records an excluded one.** | **S3** and **S4** pass on both platforms.                                                                                                                            |
| 2   | **A question is answerable with citations that resolve.**                       | **S1** (≥80% top-3 on 50 questions) and **S2** (citation integrity) pass as CI gates.                                                                                |
| 3   | **Degradation is graceful and visible.**                                        | **S6** passes, and every failure mode in [ARCHITECTURE.md](./ARCHITECTURE.md#failure-modes-and-degraded-behaviour) has a defined user-visible state.                 |
| 4   | **Memory semantics are right often enough to trust.**                           | The M3 fixtures pass in both directions — should-produce and should-not-produce — including the should-yield-zero documents.                                         |
| 5   | **Re-processing is safe and auditable.**                                        | **S5** passes for every stage: importance, extraction, chunking, embedding, distillation.                                                                            |
| 6   | **Deletion works in both directions.**                                          | **S7** passes: a complete export, and an unrecoverable hard delete.                                                                                                  |
| 7   | **The system survives being ignored.**                                          | A backup is restored successfully on the local stack; the retention sweep has run; a full corpus re-embed has been executed once.                                    |
| 8   | **Someone else could operate it.**                                              | The runbook covers every failure mode, and each has been exercised or explicitly marked untested.                                                                    |
| 9   | **It runs on real data for a sustained period.**                                | Weeks, not days, on the author's own capture stream — because the failure modes that matter (drift, backlog, topic rot, memory contradiction) only appear over time. |

### What v1 explicitly is **not**

A long list, because most of these are things a reasonable person would assume a "v1" includes.

| Not in v1                                             | Why not                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Reflection and proactive insight**                  | Built on memories, so it is meaningless before they are trustworthy. A reflection feature on noisy memories produces confident nonsense, which is worse than no feature. Scheduled as M8.                                                                                              |
| **Local-only processing**                             | The strongest privacy posture, and a re-architecture of where every stage runs. It needs a local model that passes E3 and E17 first. Scheduled as M9.                                                                                                                                  |
| **Multi-user support**                                | The schema is ready; the operations and economics are not. Committing to multi-user in v1 means committing to provider-key management, cost attribution, and abuse handling before the single-user product works. Scheduled as M10.                                                    |
| **Sharing, teams, or any collaboration**              | An explicit non-goal. It needs a sharing model that RLS-per-user actively resists, and it changes the privacy story for everyone. Scheduled as M11 and deliberately unscheduled beyond that.                                                                                           |
| **Cross-language full-text search**                   | The `fts` column uses the `english` configuration. A corpus in another language still retrieves through the vector leg; keyword search is degraded for it, and this is a known limitation rather than a hidden one ([DATABASE_SCHEMA.md](./DATABASE_SCHEMA.md#open-schema-questions)). |
| **OCR of scanned PDFs and images**                    | An explicit non-goal: it makes the system a screenshot archive, which is a different product with a much larger privacy surface.                                                                                                                                                       |
| **Server-side page rendering**                        | A headless browser to defeat JS-rendered pages would work, and it is a large new attack and cost surface. The client already has the rendered DOM — using it is the preferred fix (**E9**), and it is a phase-2 question rather than a v1 feature.                                     |
| **Browser history import**                            | Retrofitting months of history would produce a corpus with no importance signals and no exclusion list applied — which is precisely the archive this product exists to avoid.                                                                                                          |
| **A mobile web app or a third client**                | Two platforms already duplicate the queue, the dedupe key, and the scoring rubric three ways. A third doubles the drift surface for no new capability.                                                                                                                                 |
| **On-device vector search**                           | Part of M9, and it needs an on-device embedding model and a local index.                                                                                                                                                                                                               |
| **Fine-tuning or training any model on user content** | Ruled out by the privacy commitments below, permanently, not deferred.                                                                                                                                                                                                                 |
| **Real-time / streaming ingestion**                   | Nothing user-visible depends on sub-minute ingestion, and the queue design trades latency for durability on purpose.                                                                                                                                                                   |
| **A public API for third-party applications**         | Every access path is a privacy surface. An API would require an authorisation model that does not exist and a consent story that cannot be retrofitted.                                                                                                                                |
| **Analytics of any kind that includes content**       | Content-free error reporting only. This is a commitment, not a v1 limitation.                                                                                                                                                                                                          |
| **A hosted multi-tenant service with billing**        | M10's operational half, and it changes the product from a personal tool into a business.                                                                                                                                                                                               |

## Risk register

Likelihood and impact are judgements, not measurements. Each risk names what would reduce the _likelihood_ separately from what would reduce the _impact_, because for several of these the honest answer is that the likelihood cannot be lowered and the exposure must be bounded instead.

### Technical risk

| #   | Risk                                                                                                                                  | Likelihood | Impact     | Why it is a risk here                                                                                                                                                                             | Mitigation to reduce likelihood                                                                                                                                                                                                            | Bound if it happens                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T1  | **Distillation produces plausible but wrong memories.** A confident false statement about the user, cited back at them.               | High       | **Severe** | This is the least testable part of the system and the most valuable. LLMs are good at producing fluent wrong statements, and a wrong memory is worse than no memory.                              | Bidirectional fixtures (should-produce **and** should-not-produce), the should-yield-zero documents in E3, `confidence` separated from `importance`, `status: 'candidate'` for ambiguous cases, and the user correction path from phase 3. | The review queue makes a wrong memory visible and correctable. Memories are superseded rather than deleted, so a wrong statement with a history can be identified as wrong after the fact.       |
| T2  | **The client pre-score discards irrecoverably important events.**                                                                     | Medium     | **High**   | It is a data-loss decision made on the device, and the loss is silent — it looks like nothing happened. The cold-start case makes it worst exactly when the user is first evaluating the product. | **E6** and **E7** before the threshold is finalised; a conservative default threshold on the principle that dropped is unrecoverable while uploaded is merely costly; a fixture set the client asserts against.                            | Raise the threshold's permissiveness at the cost of uploading and embedding more noise, which is a spend problem rather than a loss problem.                                                     |
| T3  | **A missing RLS policy is a data leak.**                                                                                              | Low        | **Severe** | The anon key ships in clients, so RLS is the only thing standing between a public bundle and every user's data (ADR-018). A table added without policies is the failure.                          | The CI assertion that every table has forced RLS, the second assertion that every table has a policy or an explicit allowlist entry, and the two-user leak test **on every table**.                                                        | The anon-key-only rule bounds the exposure to RLS's correctness; there is no second boundary. This is why the assertions are phase-1 exit criteria and phase-7 CI gates.                         |
| T4  | **The pinned embedding dimension is the wrong choice.**                                                                               | Medium     | **Medium** | `vector(1024)` is baked into the schema, and changing it is a corpus-wide re-embed with a dual-read window (ADR-004).                                                                             | **E1** before the default is confirmed, including the asymmetry measurement; choosing a model whose width is natively available elsewhere so the escape is cheaper.                                                                        | The ADR-004 migration procedure is a cost rather than a dead end: embeddings are derived data, reproducible from source text, and the dual-read window means no downtime.                        |
| T5  | **The three scoring implementations drift.** Extension (TS), server (TS), Android (Kotlin), plus a dedupe-key implementation in each. | **High**   | Medium     | Two languages, three copies of one rubric, and a divergence in `dedupeKey` accumulates duplicate rows silently rather than failing.                                                               | A shared fixture set every implementation asserts against, before the Kotlin implementation exists; the phase-6 constant-generation decision.                                                                                              | Divergence shows up as a duplicate rate or a score disagreement, both measurable — E11 is the divergence measurement, and it exists to make this visible.                                        |
| T6  | **Extraction failure is invisible.** A page yields no text, records `failed`, and the user concludes the product does not work.       | High       | Medium     | Extraction failure modes are numerous and mostly outside our control ([RESEARCH_NOTES.md](./RESEARCH_NOTES.md#content-extraction-failure-modes)).                                                 | The `extraction_status` state machine with a recorded reason, the schema constraint that `extracted` implies text, and E10's distribution surfaced in the dashboard rather than in a log.                                                  | The failure is visible per document, so the user can see why and can supply the text manually through `/v1/ingest/document`.                                                                     |
| T7  | **Retrieval quality plateaus below the S1 gate.**                                                                                     | Medium     | **High**   | Recall is the product. If the top-3 hit rate is 40%, nothing else about the system matters.                                                                                                       | The harness exists from phase 4 and the gate is a number before it is a hope; the fusion is attributable per signal, so a regression can be traced; intent routing and reranking are both in scope if the baseline is not good enough.     | The chunks remain retrievable, so a weak memory layer degrades retrieval rather than destroying it — and the failure mode is measurable rather than mysterious.                                  |
| T8  | **Provider dependency: a model is deprecated, changes behaviour, or changes price.**                                                  | High       | Medium     | Four provider candidates all imply this. DeepSeek is the default LLM and a small vendor.                                                                                                          | The provider interface with a factory (ADR-005) makes swapping a config change; the error taxonomy and cost accounting are provider-independent; the local fallback path exists in the degrade chain.                                      | A provider change costs a config change plus a quality re-measurement, except for embeddings, where it costs a corpus re-embed. This is the strongest argument for a local embedding model (E1). |
| T9  | **The M7 durability work is skipped.** Retention, backups, restore tests, the runbook.                                                | **High**   | **High**   | It is the least interesting milestone and the system appears to work without it — until it does not.                                                                                              | Making M7 a definitional part of v1 rather than a follow-up, with a restore test and an executed retention sweep as exit criteria.                                                                                                         | A tested backup bounds the worst case. Without one, the bound is the host's default retention, which is not a bound.                                                                             |
| T10 | **The Supabase dependency becomes unacceptable.** Provider lock-in, a policy change, a pricing change, or a loss of trust.            | Low        | **High**   | RLS policies, `auth.uid()`, `auth.users` foreign keys, and edge-function idioms are all Supabase-specific.                                                                                        | Keeping business logic in ordinary Node services rather than in edge functions, so only the data layer is coupled; `supabase/migrations/` is portable SQL apart from the `auth` references.                                                | **Supabase self-hosted** keeps the API and removes the vendor, which is the escape hatch ADR-002 names. Reinstating a bespoke auth service is the expensive part.                                |
| T11 | **The corpus grows past what the design assumes.** One user's corpus is bounded, but "one user" reading for five years is not.        | Low        | Medium     | Every index choice, every full-table re-embed, and the absence of partitioning assume a personal-scale corpus.                                                                                    | The stamps that make backfills incremental, the bounded client queue, and the retention sweep.                                                                                                                                             | Range-partitioning `activity_events` by month turns retention from a `delete` into a `drop partition` — a real improvement, and a heavier schema that only becomes worth it at scale.            |

### Product risk

| #   | Risk                                                                                                                                                                                       | Likelihood | Impact     | Why                                                                                                                                                                                                                               | Mitigation                                                                                                                                                                                                                                                                                                  | Bound                                                                                                                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | **"A memory" turns out not to be a useful primitive.** The system produces statements nobody wants to read back.                                                                           | **High**   | **Severe** | This is the core bet of the product, and the three worked examples show how much judgement sits in "is this durable?". It is entirely possible the answer is "documents were enough".                                             | The M3 fixture set forces the definition to be concrete before the pipeline is built on it; the review queue gives direct evidence about which memories a human keeps versus discards; `access_count` measures which memories are actually retrieved.                                                       | If memories are unhelpful, the chunks and the hybrid retrieval still work — the product becomes a good search tool over reading history rather than a memory system. That is a worse product and a working one. |
| P2  | **The value only appears after months of use.** A memory system with an empty corpus answers nothing.                                                                                      | **High**   | Medium     | The cold-start problem is not only in the scoring rubric; it is in the product's perceived value on day one.                                                                                                                      | The activity dashboard shows value immediately (what was captured, what was important) even with no memories; the extension-only first-run import is deliberately **not** offered, so the corpus starts honest; onboarding asks for exclusions first, which is the one setup step with an immediate payoff. | Value grows with the corpus, so the bound is time rather than a defect. The risk is that the user quits before the value arrives, which no engineering fix addresses.                                           |
| P3  | **The privacy promise is not believed.** A tool that watches your browsing is a hard sell regardless of its architecture.                                                                  | Medium     | **High**   | Belief in a privacy claim is not earned by documentation. It is earned by verifiability: a local score that demonstrably drops events, an exclusion list that demonstrably records nothing, and a data path a person can inspect. | The exclusion invariant is tested (S3), not asserted; local scoring is a visible filter; the dashboard shows what was captured and what was not; the code is inspectable and the pipeline is not a black box.                                                                                               | The honest limit — synced content has already been sent to a provider — must be stated during onboarding rather than in a policy page. This lowers the promise's ceiling and raises its credibility.            |
| P4  | **Maintenance cost exceeds the value for a single-user tool.**                                                                                                                             | Medium     | Medium     | Six workspaces, three services, two clients, an external stack, and a pipeline with nine stages, all to answer questions for one person.                                                                                          | The phased plan keeps each phase independently coherent, so stopping at any point leaves something useful. Retention is bounded. The system has no message broker and no orchestration framework by design.                                                                                                 | Stopping at M4 leaves a working retrieval tool. Stopping at M5 leaves a usable product. The plan is deliberately stop-able.                                                                                     |
| P5  | **The extension's permissions scare users away, or a store review rejects it.**                                                                                                            | Medium     | Medium     | `chrome.idle` and `chrome.alarms` show in the install prompt, and history-style permissions are scrutinised.                                                                                                                      | Requesting the narrowest set that works — no `history`, no `<all_urls>` where a narrower match suffices, no accessibility service on Android. A written permission rationale per permission.                                                                                                                | A narrower permission set is a feature loss, not a redesign: fewer capture triggers mean slower sync, not lost events, because the queue is durable.                                                            |
| P6  | **Quality is judged on the wrong corpus.** The author's own reading is a biased sample — technical, English, web-heavy — and a corpus of PDFs and transcripts may behave very differently. | High       | Medium     | The evaluation set is built from one person's reading, and all quality claims are measured against it.                                                                                                                            | The fixture corpus deliberately includes a transcript, a PDF, and long unstructured essays, and the phase-7 chunking comparison is class-specific for this reason.                                                                                                                                          | Report quality per document class rather than as one number, so a class that fails is visible rather than averaged away.                                                                                        |

### Privacy and compliance risk

| #   | Risk                                                                                                                                                                                                   | Likelihood | Impact     | Why                                                                                                                                                                                                                                             | Mitigation                                                                                                                                                                                                                                                       | Bound                                                                                                                                                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | **Excluded content is captured anyway.** The strongest possible violation, because it breaks the one promise the product is built on.                                                                  | Low        | **Severe** | The invariant is enforced in application code on two platforms, and a single missed check — a new event type, a new capture path, an exclusion pattern that does not match what it should — puts the content in the queue and then in Postgres. | The check runs **before** the event object is constructed, in both clients, so there is no object to leak; S3 asserts it at the queue boundary for every event type; the settings UI shows the effective exclusion list so a user can see it is what they typed. | A retroactive rule change re-scores historical events to `noise` (ADR-009), which converges history toward the invariant as far as is possible without deleting evidence the user may want. That is a mitigation, not a reversal: capture-time exclusion is absolute, post-hoc exclusion is a converge. |
| C2  | **A provider trains on user content.**                                                                                                                                                                 | Medium     | **High**   | Embedding and distillation send content to third parties by necessity, and the terms are not uniform: some providers reserve training rights on submitted data.                                                                                 | Provider eligibility is gated on the training-data posture, and the default is chosen with it in mind; the local provider path exists as an alternative; the onboarding copy states which providers see what.                                                    | A provider's terms can change after selection. The bound is the interface (ADR-005), which makes switching a config change — except for embeddings, where it costs a corpus re-embed.                                                                                                                   |
| C3  | **Secrets leak from clients.** An extension bundle is readable; an APK is decompilable.                                                                                                                | Medium     | Medium     | Only public values ship, by rule. But a per-device secret in local storage is a bearer token, and a browser extension has no secure element.                                                                                                    | The anon-key-only rule (ADR-018), with the service-role key never leaving a server environment; per-device secrets so the blast radius is one device; hashed storage so a database read does not yield a secret; revocation as a single column write.            | The anon key is worthless without a JWT, so a leaked bundle is not a breach. A leaked device secret grants the ability to submit activity **for that one device** — an integrity problem, not a confidentiality one.                                                                                    |
| C4  | **Retention defaults retain too much, or deletion is not real.**                                                                                                                                       | Medium     | **High**   | Retention is the one place the system deletes without the user asking, and deletion is the one thing a privacy commitment must be literal about.                                                                                                | Band-based defaults with the `noise` band shortest; a hard delete that removes rows and their dependents rather than marking them; S7 asserting that a deleted row is unreachable by any application path.                                                       | The sweep is the only automated deletion and it touches `activity_events` only, so documents and memories are never silently removed.                                                                                                                                                                   |
| C5  | **Metadata leaks even when content is protected.**                                                                                                                                                     | Medium     | Low        | The platform operator sees row counts, table sizes, and request volumes (ADR-002), and an unauthenticated `/v1/health` could leak counts if it were carelessly written.                                                                         | `/v1/health` is specified to report reachability only — no counts, no ids, no user data — and that is a test rather than a convention. The main store's volume is not hidden and is stated as a limit.                                                           | Self-hosting (M9-adjacent) removes the host-visibility exposure entirely.                                                                                                                                                                                                                               |
| C6  | **Consent is not informed.** The user installs a capture tool, and the meaningful disclosure — that content goes to a third-party model provider, and that exclusions are not retroactive — is buried. | Medium     | **High**   | Both facts are genuinely important and both are easy to omit from a settings screen.                                                                                                                                                            | Onboarding asks for the exclusion list **first**, before capture starts, and states the non-retroactivity plainly. The provider configuration screen names which providers see what.                                                                             | The honest limits are in [PROJECT_OVERVIEW.md](./PROJECT_OVERVIEW.md#the-privacy-promise) precisely so they cannot be forgotten in the UI, and a compliance concern that becomes real is a copy change rather than a redesign.                                                                          |
| C7  | **The user's own content includes third parties.** An article by someone else, a client's confidential document, a colleague's message.                                                                | Medium     | **High**   | The corpus is not only the user's own material, and neither the exclusion list nor the retention policy distinguishes third-party content.                                                                                                      | Exclusion by domain and package is the primary control; retention bounds the exposure window; the export and delete paths let a user remove something specific.                                                                                                  | The stated limit is that the user is responsible for what they capture, and the product should say so rather than imply otherwise.                                                                                                                                                                      |
| C8  | **A jurisdiction-specific obligation applies** (a deletion deadline, a data-residency requirement, an access-request obligation).                                                                      | Low        | Medium     | A personal tool can still process regulated data — health portals, legal documents, client material — and residency follows the Supabase project's region and the providers' endpoints.                                                         | Region selection is a deployment choice and should be documented rather than defaulted; the export path is the access-request mechanism; the hard delete is the erasure mechanism.                                                                               | The paths exist from M7; what is missing is the documentation of which obligation each one satisfies, which is a documentation task rather than an engineering one.                                                                                                                                     |

## Privacy and data-governance commitments

Stated as commitments with a mechanism and a test, because a commitment without a mechanism is marketing. These extend the promise in [PROJECT_OVERVIEW.md](./PROJECT_OVERVIEW.md#the-privacy-promise) into something checkable.

| #   | Commitment                                                                                                                                                                                                        | Mechanism                                                                                                                                            | Verified by                                                                                                                   | In v1 |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----- |
| G1  | **No third-party training on user content, ever.** Nothing captured is used to train, fine-tune, or evaluate any model, ours or a provider's.                                                                     | Provider eligibility is gated on the training-data posture in its terms, and the local provider is the only path with no content egress at all.      | A provider-selection checklist recorded with the choice, reviewed when a provider changes.                                    | Yes   |
| G2  | **Excluded apps and domains record nothing at all.** No row, no queue entry, no counter, no redacted placeholder.                                                                                                 | The exclusion check runs before the event object is constructed, in both clients (ADR-009).                                                          | **S3** — asserted at the queue boundary, per event type, per platform.                                                        | Yes   |
| G3  | **Complete data export on demand.** Everything the system holds about the user, in a documented format, in one operation.                                                                                         | An export covering every table reachable from `user_id`, with a manifest.                                                                            | **S7** — the manifest is asserted to cover every table, so a table added without being added to the export is a test failure. | Yes   |
| G4  | **Hard delete means gone.** "Forget this" removes the row and its dependents, and no application path can retrieve it afterwards.                                                                                 | A real `delete`, not a status. Superseded memories are kept, but a _deleted_ one has no replacement and no window.                                   | **S7** — asserted by checking every table reachable from the deleted id.                                                      | Yes   |
| G5  | **Stated retention defaults, overridable, with a floor.** Raw events expire by importance band; memories do not expire by default.                                                                                | Band-based cutoffs in [DATABASE_SCHEMA.md](./DATABASE_SCHEMA.md#retention-and-ttl), a scheduled sweep, per-user overrides.                           | The sweep's dry-run mode, and the test that it deletes only `activity_events`.                                                | Yes   |
| G6  | **The user can see and correct everything the system inferred.** Every memory shows its statement, kind, confidence, evidence, sources, and the prompt version that produced it.                                  | The dashboard and the memory review queue.                                                                                                           | The document detail view resolving a memory back to its chunks and its frozen excerpt.                                        | Yes   |
| G7  | **Content never appears in logs, telemetry, or error reports.** Logs reference ids, counts, durations, and error classes only.                                                                                    | A logging discipline with content-free interpolation, and no analytics SDK with content in it.                                                       | Review, plus the assertion that no log statement interpolates `text`, `statement`, `extracted_text`, or `query`.              | Yes   |
| G8  | **The honest limits are stated to the user, not buried.** Synced content has already reached a provider; exclusions are not retroactive; a device secret is a bearer token in local storage.                      | Onboarding copy that asks for exclusions first and states the non-retroactivity; a provider screen that names what each provider sees.               | Onboarding cannot be completed without the exclusion step and the disclosure being shown.                                     | Yes   |
| G9  | **The service-role key never ships, and clients hold the anon key only.**                                                                                                                                         | The anon-key-only rule, enforced by the fact that RLS makes the anon key useless alone (ADR-018).                                                    | A check that no client workspace references the service-role variable, plus the RLS assertions.                               | Yes   |
| G10 | **The system is inspectable.** Nothing is hidden state: the pipeline's stages, the score contributions, the per-signal retrieval scores, and the memory evidence are all visible.                                 | `ImportanceScore.contributions`, `RankedChunk`'s per-signal scores, `memory_sources` with excerpts, and the version stamps.                          | The dashboard renders them; the evaluation harness reads them.                                                                | Yes   |
| G11 | **No training on interaction data either.** Click and accept feedback is not used to train a model, which rules out the "train a reranker on your own usage" option unless this commitment is explicitly revised. | This is a **decision not a default**: ADR-014's rejected alternatives include the trained reranker specifically because it would need this reviewed. | A review before any such feature is built.                                                                                    | Yes   |

## Cost projections as drivers

**No dollar figures are given.** Provider pricing changes, depends on contract terms, and would be wrong within a quarter; a number here would become a false basis for every downstream decision. What follows is what the cost _scales with_, so the model can be built from current prices at the moment it is needed.

| Driver                                    | Scales with                                                                                                                                | One-time or recurring        | What controls it                                                                                                                                                     | Levers if it is too high                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Embedding at ingest**                   | Corpus token count. The single largest recurring cost, and it is paid **once per document** plus once per re-embed.                        | Recurring, front-loaded      | How much content gets captured (the importance threshold), chunk count, and the model's price per token                                                              | Raise the threshold; a local embedding model (E1) converts this to fixed compute; a narrower model width reduces index storage and build time.              |
| **Distillation**                          | Document count × average document length, at the output-token rate for the candidate list. The most expensive per-document operation.      | Recurring, once per document | How many documents clear `DISTILLATION_MIN_BAND` (`normal`) — everything below it is captured, embedded, and searchable but never distilled — plus the model's price | A cheaper model for classification and a stronger one only for distillation; zero-memory documents cost one call rather than a retry; a higher band gate.   |
| **Chat synthesis**                        | Question count × assembled context size. Per _usage_, not per corpus.                                                                      | Recurring, per query         | Context-window budget, `RERANK_TOP_K`, and the chat model                                                                                                            | A smaller context; a cheaper chat model; the non-streamed retrieval result as a fallback when generation is unavailable.                                    |
| **Reranking**                             | If hosted: query count. If local: fixed compute, which is why the local option's cost is an artifact rather than a fee.                    | Per query, or fixed          | `RETRIEVAL_TOP_K` candidates per query (each is a forward pass)                                                                                                      | Skip reranking entirely if E5 shows the delta is small, which is a legitimate and cheaper outcome.                                                          |
| **Database, storage, and vector indexes** | Row count × vector width. A `vector(1024)` at `real4` is roughly 4 KB per vector, and an HNSW index is larger than the vectors it indexes. | Recurring, slow-growing      | Corpus size, chunk count (chunk-count inflation matters here), and the dual-window during a re-embed                                                                 | The retention sweep bounds `activity_events`; fewer and larger chunks reduce both vectors and index size; a narrower model width halves storage per vector. |
| **Backfill and re-processing**            | Corpus size × the stage being re-run. Every stamp in the schema is a potential full-corpus job.                                            | One-time, per change         | How often a rubric, extractor, embedding model, or prompt version changes                                                                                            | Stamps make backfills incremental and resumable; a stamp is only worth bumping when the change is worth the re-run.                                         |
| **Bandwidth and battery on devices**      | Captured event volume, bounded by the client's importance threshold and queue cap.                                                         | Recurring, small             | `IMPORTANCE_MIN_THRESHOLD`, `SYNC_BATCH_SIZE`, and the sync interval                                                                                                 | Raise the threshold; batch larger; sync less often. The tradeoff is latency to the dashboard, not durability.                                               |
| **Infrastructure and operations**         | Number of deployed components, not usage. Fixed.                                                                                           | Fixed                        | Three services, one web app, one Supabase project                                                                                                                    | The services are stateless and can run as a single process in aggregate; there is no broker and no orchestration framework by design.                       |
| **Maintenance (the real cost)**           | Human hours, which is the dominant cost of a single-user tool.                                                                             | Recurring                    | Workspace count, platform count, and the number of provider integrations                                                                                             | Stop at an earlier milestone (the plan is stop-able); fewer platforms; the local provider path removes an integration rather than adding one.               |

### What the cost model must show before a decision, not after

Three decisions are expensive enough that the cost must be computed **before** the change rather than reported after:

1. **An embedding model change.** Corpus-wide re-embed, plus a dual-window of doubled vector storage and a second HNSW build. ADR-004 requires the cost to be reported before execution.
2. **A corpus-wide re-chunk or re-distill.** Re-chunk implies re-embed; re-distill implies re-adjudication. Both are bounded by corpus size rather than by a delta.
3. **Changing the chat or distillation model.** A per-document or per-query price change applied to the whole history is a multiplication, not an adjustment.

## Re-architecture triggers

These are the conditions that would invalidate a structural decision rather than merely stress it. Each names the decision it would reopen and what the alternative would be. They are stated now so that firing one is a planned event rather than a surprise.

| #   | Trigger                                                                                  | What it invalidates                                                                                                              | What the alternative would be                                                                                                                                                                  | How it would be noticed                                                                                                                                                                                                                           |
| --- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **The S1 gate cannot be met at the pinned embedding width, and a wider model fixes it.** | The `vector(1024)` pin (ADR-004) and, transitively, the assumption that one width serves chunks, memories, and centroids.        | Move to a wider column via the ADR-004 dual-read migration, or move to a per-model embedding table so two models can coexist and be compared on live data — ADR-004's leading reconsideration. | The evaluation harness plateaus below the gate while a wider candidate measured in E1 clears it.                                                                                                                                                  |
| R2  | **Retrieval latency becomes provider-bound or corpus-bound in the interactive path.**    | The "one Postgres round trip" design (ADR-002) and the shared global HNSW index with a post-scan filter (ADR-003).               | An external vector store with native per-tenant filtering, or partitioning with per-partition indexes; or moving the vector leg off the request path with a cached candidate set.              | The p95 baseline's source shifts from the database to the ANN scan, or per-user filtering measurably degrades recall (E13).                                                                                                                       |
| R3  | **The client either loses events it should keep, or uploads far more than intended.**    | The local pre-score's authority as a filter (ADR-009) and the threshold as the volume control.                                   | Score locally but do not filter locally — upload everything above a coarse bar and let the server's re-score decide, which trades bandwidth and privacy-by-volume for no loss.                 | E6/E7's cold-start drop rate, or E11's client-versus-server divergence, exceeding its bound in the direction that matters.                                                                                                                        |
| R4  | **A second person needs to use the system.**                                             | The single-user assumptions throughout: one provider configuration, one corpus, no cost attribution, no per-user abuse handling. | M10, which the schema already mostly supports. The real work is operational and economic rather than structural.                                                                               | Someone other than the author asks to use it — which is a trigger for scheduling M10, not for a redesign.                                                                                                                                         |
| R5  | **Local-only becomes a requirement rather than a preference.**                           | Where every pipeline stage runs (ADR-002's hosted assumption) and the content-egress posture.                                    | M9: on-device embedding, retrieval, and distillation, which requires a local model passing E3/E17, an on-device vector store, and a client that is no longer a thin capture agent.             | E17 or a change in the user's tolerance for third-party processing. This is the largest possible change in the system's shape and the only one that would make the client the primary compute.                                                    |
| R6  | **The corpus reaches a scale where the schema's assumptions break.**                     | The absence of partitioning, the full-scan `topics` centroid read, and the assumption that a backfill is affordable.             | Range-partitioning `activity_events` by month, an indexed centroid structure, and per-stage incremental backfills with a cost ceiling.                                                         | Row counts an order of magnitude past the expectations in [DATABASE_SCHEMA.md](./DATABASE_SCHEMA.md#the-eight-tables), or a full-corpus job that no longer completes in an acceptable window.                                                     |
| R7  | **The memory layer is measured and found unhelpful (P1).**                               | The product's core premise, and by extension the distillation stage's cost and complexity.                                       | Demote memories from the primary retrieval surface to an optional layer, and make hybrid chunk retrieval the product. Cheaper, simpler, and a worse product.                                   | The review queue's accept/reject ratio, and `access_count` distribution across memories versus chunks.                                                                                                                                            |
| R8  | **A single Postgres-as-queue assumption fails.**                                         | The "no message broker" simplification (ADR-002).                                                                                | A real queue, which would matter only if a pipeline stage needed independent retry at high volume or a delivery guarantee Postgres queries cannot express.                                     | A stage that fails differently under load than under a sweep, or a backlog whose progress cannot be expressed as a `where` clause.                                                                                                                |
| R9  | **A provider's terms change so that content egress is unacceptable.**                    | The hosted-provider default for embedding and distillation.                                                                      | A local or self-hosted provider for that stage, which the interface already permits (ADR-005) — except for embeddings, where the change is a corpus re-embed.                                  | A terms revision, or a provider's training-data posture changing. This is the trigger that makes G1 and C2 real rather than theoretical.                                                                                                          |
| R10 | **The excluded-content invariant is broken in production.**                              | The credibility of the entire privacy posture, and the assumption that an application-level check is sufficient.                 | A structural enforcement: exclusion at the platform layer (a network-level block), or a capture architecture where excluded content never enters the client's process at all.                  | **S3 failing in CI, or any observed row derived from an excluded surface.** This trigger is different from the others: its response is not a redesign, it is an incident, and the first action is to find out how many rows exist and purge them. |
